# Backend Server — Hono, Prisma, Better Auth (Bun)

This backend server powers the Frontend Expo app with a minimal, fast Hono server. It provides authentication via Better Auth, JSON REST endpoints via Hono, and persistence via Prisma+SQLite.

## Stack and key decisions

- Runtime: Bun with TypeScript
- Web framework: Hono 4 with `@hono/node-server`
  - Global middleware: request logger and permissive CORS
  - Health probe at `/health`
- API: Hono routes with Zod validation via `@hono/zod-validator`
- Auth: Better Auth with Expo plugin
  - Mounted at `/api/auth/*`
  - `trustedOrigins` includes the Expo/Vibecode scheme (`vibecode://`) and localhost for development
  - Email + password enabled by default
- Database: Prisma 6 with SQLite (file DB)
  - Schema in `prisma/schema.prisma`
  - Generated client in `generated/prisma`
  - Example models: `User`, `Session`, `Account`, `Profile`, `Verification`
- Validation: Zod for input and optional env validation

## Runtime behavior

### Available Endpoints

**Auth endpoints** (`/api/auth/*`)
- Handled by Better Auth (see their docs for route list and flows)
- Includes sign-up, sign-in, sign-out, session management, etc.

**Sample endpoints** (`/api/sample/*`)
- `GET /api/sample` - Public endpoint, returns `{ message: "Hello, world!" }`
- `GET /api/sample/protected` - Protected endpoint (requires authentication)
- `POST /api/sample` - Validates request body, returns `{ message: "pong" }` when value is "ping"

**Upload endpoints** (`/api/upload/*`)
- `POST /api/upload/image` - Upload an image (multipart/form-data)
  - Field name: `image`
  - Allowed types: JPEG, PNG, GIF, WebP
  - Max size: 10MB
  - Returns: `{ success: true, url: "/uploads/...", filename: "..." }`

**AI endpoints** (`/api/ai/*`)
- `POST /api/ai/chat` - Claude AI chat with conversation history
  - Requires authentication (Better Auth session or Supabase JWT)
  - Body: `{ messages: Array<{role: "user"|"assistant", content: string}>, conversationId?: string, creatorContext?: string }`
  - Returns: `{ conversationId: string, response: string, messages: Array<ChatMessage> }`
  - Uses Claude Sonnet 5.5 (`claude-sonnet-5-5`)
  - Keeps `BACKEND_ANTHROPIC_API_KEY` (or `ANTHROPIC_API_KEY` fallback) server-side only
  - Backend startup requires the SQLite datasource and `DATABASE_URL=file:./dev.db`, which resolves to the existing `prisma/dev.db`; Supabase login/cloud sync uses its separate URL and publishable key
  - `BETTER_AUTH_SECRET` must contain at least 32 characters; changing it can invalidate existing Better Auth sessions
- `POST /api/ai/ideas` - Generate content ideas with Claude
  - Body: `{ audience: string, niche: string, tone: string, platforms: string[], hooks?: string }`
  - Returns: `{ ideas: string[] }` (array of 10 content ideas)
- `POST /api/ai/viral-score` - Analyze a social video URL and return a detailed viral score
  - Requires authentication (Better Auth session or Supabase JWT)
  - Body: `{ url: string, language?: "de" | "en" }`
  - Returns a 1–100 score, five 1–10 dimensions, strengths, weaknesses, and improvements
  - Claude transport/configuration failures are returned as JSON `502`/`503`/`504` responses
- `POST /api/ai/transcribe` - Transcribe recorded audio using OpenAI Whisper (Claude has no speech-to-text endpoint)
  - Authenticated JSON body: `{ audioBase64: string, mimeType?: string, language?: string }`; recordings must be under 25 MB
- `POST /api/ai/image` - Generate an image using OpenAI, keeping the key on the backend
  - Authenticated JSON body: `{ prompt: string }`; returns `{ url: string }`
- `POST /api/ai/extract-script` - Full recreation script (video analysis, hook analysis, second-by-second script, pacing & style, tips) generated by Claude from real video data for a YouTube, Instagram or TikTok link
  - Source material gathered first, then passed to Claude (120s timeout, output ~2000 tokens):
  - YouTube: public captions via `youtube-transcript` (no download)
  - Instagram / TikTok: `src/services/videoTranscript.ts` downloads the video, converts it to a small mono mp3 with `ffmpeg`, and transcribes it with OpenAI Whisper (language auto-detected)
    - TikTok media is resolved through the public `tikwm.com` API (TikTok blocks `yt-dlp` from datacenter IPs); `yt-dlp` and the page's `og:video` tag are fallbacks
    - Instagram media is resolved with the bundled `bin/yt-dlp` (requires `python3` on the host); `og:video` is the fallback
    - Music-only clips use the caption as source (`hasTranscript: false`); if the download fails (private video, blocked), the route falls back to page metadata so a script is still produced
  - Requirements on the host: `ffmpeg`, `python3`, and `bin/yt-dlp` (update with `./bin/yt-dlp -U`, or set `YT_DLP_PATH`)


**Static files** (`/uploads/*`)
- Serves uploaded images from the `uploads/` directory

**Health check** (`/health`)
- Returns `{ status: "ok" }` for monitoring and load balancers

### Middleware Stack

1. **Request logger** - Logs all incoming requests with method, path, status, and response time
2. **CORS** - Enabled for all routes by default (customize in production)
3. **Auth middleware** - Extracts session from headers and attaches user/session to context

### Logging

The server includes comprehensive logging for debugging and monitoring:
- 🔧 Server initialization and configuration
- 🌐 Middleware setup (CORS, auth, etc.)
- 👤 Authentication events (session found/not found)
- 📤 Upload process (file validation, saving, errors)
- 📝 Route access (sample endpoints)
- 💚 Health checks

All logs use prefixes like `[Upload]`, `[Sample]` for easy filtering.

## AI Configuration

The backend provides secure AI integration through Claude via the Anthropic SDK:

- **API Key**: Set `BACKEND_ANTHROPIC_API_KEY` in the backend environment (takes priority)
- **Workspace**: If the key is not scoped to a single workspace, set `ANTHROPIC_WORKSPACE_ID` to the `wrkspc_…` ID shown in Claude Console → Settings → Workspaces. The backend sends it as `anthropic-workspace-id` on every Claude request. Alternatively, use a key scoped to one workspace; never put the key in mobile environment variables.
- **Fallback**: Uses `ANTHROPIC_API_KEY` or proxied key if backend key not set
- **Base URL**: A configured `BACKEND_ANTHROPIC_API_KEY` uses `https://api.anthropic.com` explicitly. Without it, the client uses the Vibecode proxy URL from `ANTHROPIC_BASE_URL`.
- **Reliability**: Claude requests use a 45-second timeout and at most one automatic retry.
- **Security**: API key is NEVER exposed to the frontend. All Claude calls happen server-side.
- **Model**: Uses `claude-sonnet-4-6` for chat and content ideas
- **Token Limit**: 4000 tokens max per chat response, 1500 for content ideas
- **Speech and images**: Configure `OPENAI_API_KEY` for direct OpenAI Whisper and image generation. If using a proxy instead, configure `OPENAI_BASE_URL` accordingly. These capabilities cannot use the Claude text API.
- **Access**: Routes require authentication, but Pro entitlement and usage limits are not checked server-side yet; add server-side enforcement before production billing depends on it.

## How to Add New Routes

This template follows a modular route structure. Here's how to add new endpoints:

### 1. Create a new route file in `src/routes/`

```typescript
// src/routes/todos.ts
import { Hono } from "hono";
import { type AppType } from "../types";

const todosRouter = new Hono<AppType>();

todosRouter.get("/", (c) => {
  // Access user context if needed
  const user = c.get("user");
  
  console.log("📋 [Todos] Get all todos requested");
  // Your logic here
  return c.json({ todos: [] });
});

todosRouter.post("/", async (c) => {
  console.log("➕ [Todos] Create new todo requested");
  // Your logic here
  return c.json({ success: true });
});

export { todosRouter };
```

### 2. Mount the router in `src/index.ts`

```typescript
import { todosRouter } from "./routes/todos";

// ... in your app setup
console.log("📋 Mounting todos routes at /api/todos");
app.route("/api/todos", todosRouter);
```

### 3. Key Patterns

- **Use `AppType`** for type-safe context access (`c.get("user")`, `c.get("session")`)
- **Add console logs** with emoji prefixes for visibility (e.g., `[Todos]`)
- **Validate input** with Zod using `@hono/zod-validator`
- **Check auth** by verifying `c.get("user")` is not null
- **Follow naming** convention: `feature.ts` (not `feature.route.ts` or `featureRouter.ts`)

## Scripts

- `bun run dev`: start the backend server in development with hot reload. You don't have to do this since the Vibecode dev backend server will automatically restart the backend server when you make changes to the code.
- `bunx prisma generate`: generate Prisma client
- `bunx prisma migrate dev --name <migration-name>`: sync schema to the database and generate a new Prisma client
- `bun install` also generates the new Prisma client in its postinstall step
